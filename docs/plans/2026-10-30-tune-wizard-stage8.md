### Задача 1: сервер `serve.ps1`, `Мастер настройки.cmd`, тест сервера

**Файлы:** создать `TuneWizard/windows/serve.ps1`, `Мастер настройки.cmd` (корень), `tests/tunewizard-serve.cjs`; изменить `package.json` (`"test:tunewizard-serve": "node tests/tunewizard-serve.cjs"`).

- `serve.ps1` — по разделу 3 дизайна: параметры `-Root` (по умолчанию — два уровня выше скрипта), `-Port` (по умолчанию 8000), `-NoBrowser` (для теста); `TcpListener` на `127.0.0.1`; GET/HEAD; нормализация пути, 403 вне корня (в том числе `%2e%2e`, `..\`, абсолютные, `\`), 404, папка → `index.html`, без косой черты → 301; типы файлов (`.js` — `text/javascript; charset=utf-8` обязательно); `Cache-Control: no-cache`, `Connection: close`; ошибка запроса — 500 и строка в консоли, сервер работает дальше; порт занят — проверка `GET /TuneWizard/` (`<title>Мастер настройки`): мастер — открыть браузер (если не `-NoBrowser`) и выйти с кодом 0; чужая программа — сообщение, ожидание клавиши (если консоль интерактивна) и код 1. Сообщения — по-русски, коротко, комментарии-контракты перед функциями.
- `Мастер настройки.cmd` — по разделу 4 дизайна, только латиница внутри.
- `tests/tunewizard-serve.cjs` (по образцу `tests/tunewizard-prep-browser.cjs`: Chrome через `CHROME_PATH`, `finally`, свой порт — 8797): запустить `powershell -NoProfile -ExecutionPolicy Bypass -File TuneWizard/windows/serve.ps1 -Root <корень> -Port 8797 -NoBrowser`; HTTP-проверки (типы `.js`, `.json`, `.html`, `.png`; 404; 403 на `/../package.json`, `/%2e%2e/package.json`, `/TuneWizard/..%5c..%5cpackage.json`; 301 на `/TuneWizard`; HEAD без тела); страница мастера в Chrome — `DataflashParser` загружен (`await import_done`), описания параметров пришли (`step_load_metadata()` без сбоя), загрузка `tests/fixtures/prep.param` — блок подготовки виден, ошибок консоли нет; «Открыть в FilterReview» не проверять кнопкой — открыть `/FilterReview/` и `/PIDReview/` напрямую без ошибок консоли; второй запуск на том же порту — завершается сам с кодом 0, не поднимая второй сервер; порт, занятый чужим сервером (простой `http.createServer` из теста) — код 1 и сообщение. Корень — аргументом командной строки теста (по умолчанию корень репозитория), чтобы задача 2 прогнала тот же тест на переносной папке.
- Вручную: запуск `Мастер настройки.cmd` из `cmd.exe` открывает мастер; загрузить второй лог, пройти шаги 0–5.

**Коммит:** `TuneWizard: запуск двойным кликом — сервер на PowerShell и тест`, push.

### Задача 2: сборка переносной папки

**Файлы:** создать `tests/tunewizard-portable.cjs`; изменить `package.json` (`"tunewizard:portable": "node tests/tunewizard-portable.cjs"`), `.gitignore` (`dist/`).

- По разделу 5 дизайна: состав, проверка ссылок трёх страниц (`TuneWizard/`, `FilterReview/`, `PIDReview/` — все `src`/`href` и `import(`/`fetch(` с относительными путями должны быть в папке, иначе ошибка сборки), `Прочитай меня.txt` (текст — в скрипте, по-русски: что это, как запустить, «Запустить?» Windows для файла из интернета, закрыть окно — остановить, Chrome или Edge, память прохода — в браузере по адресу `127.0.0.1:8000`, версия: дата и коммит, «+изменения» при незакоммиченном), `Мастер настройки.cmd` и `TuneWizard/windows/serve.ps1` в папке, zip через `powershell Compress-Archive`. Выход — `dist/Мастер настройки <ГГГГ-ММ-ДД> <коммит>/` и `.zip`; параметр `--out <папка>` для теста. Вывод — путь, число файлов, размер папки и архива.

- Вручную: распаковать zip в другую папку (например, во временную), запустить `.cmd` из неё — мастер открывается, второй лог — шаги 0–5, «Открыть в FilterReview» работает.
