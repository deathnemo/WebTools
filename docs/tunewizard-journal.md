## 1. Как продолжить на другом компьютере

**Нужно установить:** Git, GitHub CLI (`gh`), Node.js не ниже 22.13 (здесь стоит 24.22.1), Python 3 (здесь 3.13), Google Chrome, VS Code.

**Получить код:**

```
git clone https://github.com/deathnemo/WebTools.git
cd WebTools
git remote add upstream https://github.com/ArduPilot/WebTools.git
git submodule update --init
git checkout <текущая ветка из раздела 4>
npm ci
```

`git submodule update --init` без `--recursive`: у `modules/ardupilot` 15 вложенных подмодулей, мастеру они не нужны. Мастер использует `modules/JsDataflashParser`, `modules/plotly.js`, `modules/fft.js`.

**Перенести вручную** (в git их нет):

- тестовый лог `TuneWizard/logs/2026-06-18 18-54-42_anon.bin` (95 МБ, чужой лог, анонимизирован). Без него браузерные тесты пропускаются;
- локальные настройки VS Code `.vscode/settings.json` (папка `.vscode/*` в `.gitignore`, кроме файлов upstream):

```jsonc
{
    "search.exclude": { "modules": true },
    "liveServer.settings.NoBrowser": true,
    // Hosting via the python launch configs; don't prompt for the recommended Live Server extension
    "extensions.ignoreRecommendations": true,
    // WebTools has no C# code; stop C# Dev Kit loading the legacy .csproj files
    // from nested submodules of modules/ardupilot (lwip, waf)
    "dotnet.defaultSolution": "disable",
    // Only its libraries/ headers are used; don't open it (and its 15 nested submodules) in Source Control
    "git.ignoredRepositories": ["modules/ardupilot"]
}
```

**Запуск мастера:** из корня репозитория `python -m http.server --bind 127.0.0.1`, затем открыть `http://127.0.0.1:8000/TuneWizard/`.

**Проверки:**

```

npm test
CHROME_PATH="<путь к chrome.exe>" npm run test:tunewizard
CHROME_PATH="<путь к chrome.exe>" npm run test:tunewizard-compare
```

## 2. Цель и рамки

Свой инструмент, который объединяет FilterReview и PIDReview из ArduPilot WebTools в **пошаговый мастер настройки Copter** по одному логу `.bin`. Шаги:

0. лог и проверки;
1. спектр до фильтров;
2. гармонический notch;
3. низкочастотные фильтры;
4. PID по осям;
5. сводка и файл `.param`.

Мастер предлагает значения, пользователь подтверждает.

- **Личный проект.** Форк `github.com/deathnemo/WebTools`, только для себя и своих компьютеров. В upstream ArduPilot ничего не отправлять: ни PR, ни issue (решение 24.10.2026). Не предлагать.
- **Только Copter**, интерфейс на русском.
- **Архитектура «A».** Новая папка `TuneWizard/`. Ядро `TuneWizard/core/` без DOM — те же файлы гоняются под Node. Математика переносится из FilterReview «минимальным диффом». Оригинальные страницы не меняются, поэтому `git pull upstream` проходит без конфликтов.
- **Оформление:** только тёмная тема «Графит» (решение 24.10.2026). Светлую тему и переключатель не делать. Шрифты Archivo и IBM Plex. Графики — Plotly, цвета из токенов CSS.

## 8. Грабли и находки

- **Парсер логов.** Для сообщений с экземплярами (VIBE, ESC, IMU, GYR, FTN, BAT, BARO) `log.get(name)` падает. Читать через `Object.keys(log.messageTypes[name].instances)` и `log.get_instance(name, inst, field)`.
- **Batch-логи.** `smp_rate` меняется от пакета к пакету: на тестовом логе 187 разных значений. FilterReview брал частоту первого пакета, оси частот смещались в 1.000334 раза (дефект 1, исправлен в мастере).
- **Тестовый лог:**
  - ArduCopter 4.6.3, версия фильтра 2, batch IMU до и после фильтров, ESC-телеметрия на 4 моторах;
  - газ висения ≈ 0.12 при `MOT_THST_HOVER 0.30`;
  - P = I по крену и тангажу, I рыскания = 0.1·P — следы AutoTune;
  - шаг 2 рекомендует «Как в логе + второй notch на 153 Гц» (`INS_HNTC2` FREQ 153, BW 22, ATT 30, MODE 0).
- **Шаг 3:**
  - в 4.6 пределы ускорения называются `ATC_ACCEL_*_MAX` и задаются в сантиградусах/с²; в новых версиях — `ATC_ACC_*_MAX` в °/с²;
  - AutoTune сам записывает пределы ускорения, поэтому формула предлагается только при заводских 1100 / 270 °/с²;
  - на тестовом логе задержка «как в логе» — путь P 9.9 мс, путь D 13.4 мс на 30 Гц. Notch стоит на каждом из 4 моторов (`INS_HNTCH_OPTS 6`), это даёт +2.9 мс против одного notch на гармонику.
- **Модель шага 3:** Kd = 0 — «D выключен» (путь D не проверяется), нет Kd в логе — «неполные данные»; notch ошибки ПИД (`NEF`) и быстрый поток контура (`FSTRATE_ENABLE`, Copter 4.7) моделью не учтены — только предупреждение; пустое поле фильтра в форме даёт NaN и отметку варианта.
- **Правки полей шага 3** пересчитываются через 400 мс после набора (`input`), `change` — только при отличии; кнопки «Применить вариант» / «Принять» сами досчитывают правки. Иначе перерисовка при потере фокуса сдвигала кнопку и щелчок терялся. В браузерных тестах после `fill` ждать устоявшуюся таблицу через `waitForFunction` (`step3.edit_timer == null`), а не фиксированной паузой.
- **Полностраничный снимок Playwright** меняет размер окна, и Plotly ставит всем графикам `autosize` — это маскирует дефекты ширины. Проверки ширины графиков делать до первого снимка (так устроена проверка после перезагрузки страницы в конце браузерного теста).
- **Форма параметров шага 3** строится своим кодом, а не `Libraries/ParameterMetadata.js`. Поле `INS_GYRO_FILTER` уже есть в форме шага 2 (элементы ищутся по `id` = имени), а старых имён `ATC_ACCEL_*` нет в `FilterReview/params.json`.
- **Защита Claude Code** блокирует Claude слияние в `main` и push в `main` («Merge Without Review»), даже с устным разрешением. Такие команды пользователь выполняет сам, Claude даёт их текст.
- **Субагентов иногда прерывают лимиты сеанса.** Их работа сохраняется, их можно продолжить.
